Кэш задач живёт только внутри tick. `store.latest_runs` и индексы убирают сканирование полной истории. Не возвращайте отдельное соединение на каждую задачу или строку времени. ## Продуктовые ограничения

Орбита — самостоятельная локальная панель автоматизаций, проектов, уведомлений и практики для разных пользователей. Не привязывайте новые сценарии к городу, распорядку или оборудованию автора. Пользовательский профиль пустой при установке; обучение и автоматизации включаются только после настройки. Корпоративные системы, почта и обязательные облачные API в текущий продукт не входят.

Стеклянная тёмная палитра с мятными акцентами одобрена. Прямоугольные артефакты за скруглёнными углами исправлены в 0.4.1. Пользователь просит продолжать визуальную доработку и реальные возможности, очищать обычный UI от тестовых элементов. В каждом итоговом ответе нужна ссылка на **папку готовой программы**, путь вычисляется относительно текущего checkout: `dist/Orbita`.

## Реализовано

- Независимый от Qt/Windows планировщик с сохранёнными задачами, одноразовыми/повторяющимися расписаниями, ограниченными повторами, арендой выполнения и защитой от повторов планового слота.
- Прогноз выбранного места, системное определение по согласию, поиск городов и ручные координаты, личные напоминания с выполнением/откладыванием, аудит по реальному журналу, выключенная до настройки задача практики Db2.
- Обучение: диагностика и шесть полноценных практик, ответы/заметки/самооценка, постепенные подсказки, скрытый эталон, копируемый вопрос для Codex. SQL сохраняется как текст. В настоящей Db2 материалы не исполнялись; результаты отдельно проверены вычислениями в Python.
- Проекты: шаблоны ПК/3D-печать/дача, чек-лист, заметки, HTTP(S)-ссылки, статусы, одно связанное напоминание, отмена при закрытии проекта.
- «Сегодня»: реальные ожидающие напоминания, их отложенное состояние, сегодняшнее расписание/ожидающие запуски, следующие шаги активных проектов. Это read model, не отдельный планировщик.
- Трей, пауза, тихий режим, сохранение геометрии/закрепления, необязательный автозапуск Windows.
- JSON-публикация прежними командами; интернет нужен для свежей погоды, поиска города и уточнения пояса device-координат.
- В 0.5.0 общие Qt-компоненты вынесены из главного окна, пути данных выделены в `app_config.py`, документация включена в пакет, сборщик перестал зависеть от имени пользователя разработчика.

## Как продолжить в новом чате

1. Прочитать `AGENTS.md` и комплект из `START_HERE.md`.
2. Проверить актуальную версию по `app_config.VERSION`, схему по `desktop_store.SCHEMA_VERSION`, реальную базу и локальные изменения. Не восстанавливать старую базу поверх новых данных ради удобства.
3. Для новой платформы выбрать один вертикальный сценарий: запустить UI → сохранить проект → закрыть/открыть → доставить локальное напоминание → обработать клик. Сначала подтвердить жизненный цикл и упаковку, затем переносить остальные экраны.
4. Использовать тесты и команды из `BUILDING.md`. Не считать прохождение импортов на Windows проверкой macOS или Android.
5. После изменения возможностей обновить руководство, `CHANGELOG.md`, этот файл и соответствующий архитектурный документ. Собрать/проверить пакет на поддерживаемой платформе и дать ссылку на папку программы.
