# Архитектурные решения

## 001. Прикладная логика отделена от оболочки

**Принято.** Планирование, контент, проекты, прогресс и «Сегодня» работают без Qt/Win32. Настройки путей и времени — в `app_config.py`. Общие Qt-компоненты — в `ui_components.py`, а не импортируются из главного окна. Это позволяет менять оболочку и проверять зависимости отдельно. Хранилище пока функциональное SQLite API, не универсальный ORM и не сетевой репозиторий.

## 002. Локальная работа и стабильные данные

**Принято.** Пользовательские данные находятся вне каталога exe, схема версионируется, перед миграцией делается проверенная копия. Перенос приложения на другую ОС не даёт права сбрасывать данные или менять смысл ID/состояний. Свежая погода требует сети; остальная текущая работа может быть локальной. Обязательная почта, платный API и сервер не вводятся.

## 003. Разделены журнал, пользовательское событие и действие

**Принято.** Успех обработчика — запись запуска; показ/прочтение — состояние события; выполнение/откладывание — состояние напоминания. Эти операции не взаимозаменяемы. Завершение занятия пользователем тоже не является проверкой правильности SQL. Синхронизация в будущем обязана сохранить эти различия.

## 004. Платформы имеют собственные жизненные циклы

**Принято.** Нет обещания «собрать один exe для всех». Desktop-сборки создаются нативно. На мобильных платформах сначала проверяется жизненный цикл и доставка локального уведомления. Существующий постоянно работающий поток не выдаётся за мобильный механизм фона. Android TV требует отдельной навигации и крупной панели. Мобильный стек ещё не выбран окончательно.

## 005. Стеклянная форма принадлежит Qt

**Принято в 0.4.1.** Системная подложка Windows на весь HWND создавала прямоугольный след даже при нулевой альфе углов. Теперь форма/градиенты/сглаживание рисуются Qt, системная подложка окна отключена. Не возвращать whole-window blur или грубую оконную маску без настоящей compositor-проверки. Визуально похожий QWidget screenshot сам по себе недостаточен.

## 006. Производственный UI не является галереей тестов

**Принято в 0.5.0.** Удалены кнопка демонстрационного уведомления и галерея сцен. Категория `Демо` скрыта из пользовательских выборок, но сохранена в истории SQLite. Диагностические режимы отделены от обычного запуска. Журнал, ручной запуск и учебная диагностика остаются полезными функциями, а не удаляются по слову «проверка».

## 007. «Сегодня» — read model

**Принято в 0.5.0.** Обзор читает согласованные данные задач/событий/проектов, ничего не запускает и не подделывает прогресс. Он не дублирует расписания и не становится вторым источником истины. JSON-совместимая модель пригодна для будущего UI, но не считается готовым HTTP API.

## 008. Документация — часть выпуска

**Принято в 0.5.0.** Исходники, руководство, handoff, карта данных/контрактов, ограничения платформ, аудит UI и история решений обновляются вместе. Сборка копирует документы в `docs` пакета. Текущий факт подтверждается отчётом/исходником; планы явно отделяются от реализованного. Снимок документации полезен в новом чате, но исходный код всё равно нужен.

## 009. Явное место и IANA-пояс (0.6.0)

Установка не означает согласие на геолокацию. Свежая база без города; прежняя база сохраняет известный legacy-профиль. Датчики принадлежат UI-адаптеру; сервис хранит профиль и выполняет public HTTP. Определение по IP исключено из-за VPN/неточности. Непрерывного отслеживания нет. Смена места меняет погоду/тихие часы, но не пояс существующих напоминаний. Старое смещение меток оставлено как формат хранения, чтобы не ломать текстовые сравнения SQLite и ключи прежних запусков. IANA и DST применяются на уровне календарного расчёта. Подробнее: GEOLOCATION.md.

## 010. План будущего дня не является журналом исполнения (0.7.0)

Будущие события вычисляются из действительных расписаний и snooze в отдельной read model, а не заранее вставляются в events/runs. Дата определяется IANA-поясом места; расписание сохраняет свой пояс. Требуется перечисление всех слотов дня, поскольку next_due не покрывает 25-часовой день. Погодный кэш разделён по ISO-датам с точным fingerprint и совместимым старым ключом. Если нужного дня нет, UI не переименовывает сегодняшние данные. Контракты и причины: TOMORROW.md.

## 011. Ограниченная работа вместо постоянного полного обновления (0.8.0)

Сначала измерены реальные узкие места на изолированной базе, затем добавлены индексы, пакетное enqueue и порционное создание Qt-карточек. Не вводится кэш плановых слотов между tick: это усложнило бы восстановление после сна и изменение расписания. При конкуренции окончательный статус и retry_at проверяются в пишущей транзакции. Неизменяемый фон кэшируется по размеру/DPR с сохранением альфа-канала; цены в памяти и измерения описаны в PERFORMANCE.md. Анимации выключаются отдельным пользовательским флагом, а тихий режим по-прежнему относится только к доставке уведомлений.

## 012. Общая поставка отделена от контекста автора (0.9.0)

Данные не поставляются с exe, а начальный профиль пустой. Часовой пояс без погоды настраивается отдельно; место не угадывается по прежней константе. Существующие базы и расписания сохраняют свои значения. Публичная справка берётся по allowlist из release_docs; документация разработки остаётся в исходниках. Это позволяет передавать полный инженерный контекст новому разработчику, не включая личный журнал в пользовательский пакет. Portable-структура проверяется запуском из другого пути без Python в PATH; установщик требует отдельного этапа.
