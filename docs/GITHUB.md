# GitHub и подготовка первого выпуска

Владелец: **Technomedved**, имя: **orbita**. Согласованный первый этап — приватный
репозиторий; лицензия собственного кода — MIT. Открытие репозитория и первый
Releases — следующие этапы. Репозиторий создан: https://github.com/Technomedved/orbita (private).
Origin: `https://github.com/Technomedved/orbita.git`.
Фактическое подключение проверяется `git remote -v`; серверная загрузка — `git ls-remote origin`.

## Состав

В Git: исходники, тесты, вымышленные учебные данные, документация и сборка.
Исключены data/dist/build, среды Python/Qt, базы, почтовые секреты и локальный
архив прежнего эксперимента. Старые файлы остаются на диске, не удаляются.

`.gitignore` не защищает уже отслеживаемые файлы. `check_repository.py` читает
Git index, проверяет запрещённые пути, известные форматы секретов и размеры.
Выводит только пути/категории, не значения. Это дополнительная проверка,
не гарантия отсутствия любых личных сведений. Просматривайте состав коммита.
Опубликованный секрет нужно отозвать; удаления файла из нового коммита недостаточно.

## Цикл изменений

1. Ветка, изменение и подходящие проверки.
2. `git add` конкретных файлов и `git diff --cached`.
3. `python check_repository.py`, коммит, отправка ветки.
4. Проверка и объединение в main.

Не храните токены в origin, файлах, командах или логах. Используйте Git credential
manager. Для автора коммитов используйте GitHub noreply вместо личной почты.

## До публичного выпуска

- Проверить чистое клонирование и установку закреплённых зависимостей.
- Проверить состав исходников, лицензии, ресурсы и бинарные уведомления.
- Принять отдельное решение об открытии репозитория.
- Создать тег на проверенном коммите и приложить соответствующую сборку в Releases.
  Архив Source code не заменяет готовый exe.
- Явно указать отсутствие подписи и установщика у текущей переносимой беты.
- Позже добавить CI/сборки и обновления; пока они не реализованы.

На этом этапе меняется подготовка исходников, не продукт и не схема базы.
Ранее собранный Windows-пакет остаётся прежним.

## Подготовка 0.9.1

Добавлен workflow Source checks: push main, pull_request, ручной запуск. Он проверяет Git index и ядро на Windows, не публикует релизы и не имеет прав записи. Автоматическая desktop-сборка пока не настроена.

Команды выпуска: prepare_licenses.py → commit → build_desktop.py → проверки exe → release_artifacts.py. Архивы в dist/releases; библиотечные источники обязательны рядом с Windows-архивом. Выпуск сначала готовится как draft/pre-release в приватном репозитории. Открытие репозитория остаётся отдельным действием после проверки состава. Реальный статус CI и загрузки активов проверяется по GitHub API/странице; наличие workflow не означает успешный прогон.
