# Производительность · 0.8.0

## Что изменилось

- Схема 7 добавляет семь индексов, не удаляя историю. Последний запуск читается индексированным поиском на задачу; цепочки напоминаний и календарные диапазоны не сканируют всю историю.
- Планировщик собирает слоты пачкой, переиспользует карту задач внутри прохода, не открывает пишущую транзакцию для каждого уже выполненного слота. SQL выбирает готовые попытки, а перед захватом повторно проверяются статус и retry_at под блокировкой. UNIQUE(task_id,slot) сохранён.
- Настройки читаются одним снимком. При форматировании строк используется загруженный IANA-пояс. Скрытая лента обновляется при открытии, а не на каждую запись журнала в фоне; уведомления продолжают доставляться.
- Статический фон окна кэшируется по размеру и масштабу экрана. Прозрачные углы сохранены. Пустая погода статична; анимации останавливаются при скрытии/минимизации. За пределами viewport кадры не рисуются. Пользователь может выключить «Анимации погоды», сохранив иллюстрации.
- Задачи и проекты открываются порциями по 20 карточек. Поиск проектов ждёт 200 мс; фильтр и лимит применяются в SQL до получения карточек со счётчиками шагов. Прежний сервисный API без limit возвращает полный список.

## Методика и измеренные числа

Windows 11 Pro 10.0.26300, AMD Ryzen 7 7435H, 8 ядер / 16 логических процессоров, около 15,7 GiB доступной системе RAM; Python 3.12.14, Qt/PySide6 6.12.0. Проверялась эта Windows-среда, не набор разных компьютеров и ОС. Интернет в бенчмарках не используется.

`benchmark_history.py` каждый раз создаёт временную базу: 200 включённых задач, 60 000 успешных запусков, 20 000 событий, включая 200 ожидающих напоминаний. Пять последовательных измерений каждой операции, ниже медиана. Холостой tick не выполняет обработчики, все текущие слоты уже завершены. До изменения измерялся исходный 0.7.0; данные пользователя не использовались.

| Операция на нагрузочной базе | 0.7.0 | 0.8.0 |
|---|---:|---:|
| Формирование «Сегодня» | 403,64 мс | 8,08 мс |
| Формирование «Завтра» | 17,23 мс | 6,83 мс |
| Холостой проход планировщика | 140,22 мс | 17,16 мс |
| Открытия SQLite на такой проход | 206 | 6 |

Это время конкретных операций, не обещание, что всё приложение ускорилось в 50 раз. Файлы исходных результатов: `data/performance-before-history.json`, `data/performance-after-history.json` в проекте.

`benchmark_desktop.py` измеряет импорт UI, создание и обработку первого окна внутри Python; это **не холодный запуск exe**. После 0,5 с установления состояния идут 8 с видимой панели, затем 0,5 с и 8 с скрытой. CPU = process_time / фактическая длительность, процент **одного логического ядра**, не всего компьютера. Память — working set процесса из GetProcessMemoryInfo; private usage записан отдельно. Три сцены: солнце, дождь, снег. Продвижение phase записано, чтобы отличать анимацию от статичной картинки.

В последовательном контрольном сравнении одним инструментом:

| Показатель | 0.7.0 | 0.8.0 |
|---|---:|---:|
| Создание окна с импортом, прогретые файлы | 0,915 с | 0,951 с |
| CPU с тремя анимациями | 7,81% ядра | 5,47% ядра |
| CPU после скрытия | 0,39% ядра | 0,20% ядра |
| Working set с анимациями | 137,4 MiB | 142,1 MiB |
| Private usage с анимациями | 64,8 MiB | 70,0 MiB |

Кэш фона обменивает около 5 MiB памяти в этом окне на меньшую отрисовку. В отдельных прогонах 0.8.0: пустой прогноз — 0,20% ядра / 143,5 MiB; три погодные иллюстрации с выключенной анимацией — 0,39% / 142,8 MiB; скрытая панель — 0,00% в обоих прогонах. Это близко к пределу разрешения короткого замера, не гарантия буквально нулевой нагрузки. При работающих задачах нагрузка зависит от обработчика и размера его результата.

Контрольные файлы: `data/performance-clean-before-animated.json`, `data/performance-clean-after-animated.json`, `data/performance-clean-after-idle.json`, `data/performance-after-static-weather.json`. Ранние прогоны дают более широкий разброс; два предварительных цикла частично пересеклись и в сравнительную таблицу не включены. Частота CPU, кэш ОС, другие окна и нагрузка системы влияют на результат. Ускорение запуска и снижение памяти не заявляются. Холодный запуск exe и длительная автономность на батарее не измерены.

## Повторение и регрессии

Запускайте последовательно, без одновременно идущих тестов, сборки и других бенчмарков:

```text
python benchmark_history.py --output data/performance-history.json
python benchmark_desktop.py --animated --output data/performance-motion.json
python benchmark_desktop.py --animated --no-motion --output data/performance-static.json
python benchmark_desktop.py --output data/performance-idle.json
```

Для проверки старого кода тем же инструментом используйте `benchmark_desktop.py --source <папка исходников> ...`. Не сравнивайте холодный импорт одного процесса с прогретым импортом другого как улучшение старта. Для прямого запуска Qt вне venv на текущем ПК нужен путь к `.ui-runtime`, см. BUILDING.md.

`test_performance.py` проверяет v6 → v7 с полным сравнением таблиц/backup, отсутствие повторного импорта weather_day, ограниченное число подключений, отсутствие записи revision при холостом проходе, одновременные движки, восстановление, будущие повторы и гонку retry_at, последний run по id, цепочку snooze, кириллический поиск и limit. UI-проверки проверяют отложенную ленту, порции карточек, debounce, сохранение настройки и остановку анимаций. Числа времени не превращены в нестабильные требования к чужим компьютерам.

`verify_performance_release.py` проверяет миграцию и два перезапуска настоящего exe на отдельной заполненной базе. Общие проверки пакета — `verify_product_release.py`, `verify_tomorrow_release.py`; прозрачность через реальный Windows compositor — `Orbita.exe --verify-corners <префикс>`. Отчёты хранятся в `data`. Рабочая база перед обновлением отдельно сохранена и сравнена: `data/performance-user-migration.json`.

## Результат проверки релиза

Прошли 156 общих тестов, из них 108 — ядро; пропусков и ошибок нет. Готовый Windows exe прошёл 12 функциональных запусков с кодом 0 на временных базах. Проверка реального compositor при фактических Qt DPR 1,25 и 1,5625 подтвердила прозрачные углы во всех 5 состояниях каждого прогона (RGB delta=0, alpha=0). Дополнительный масштаб задан окружением процесса поверх системного; физическое переключение мониторов не проверялось. Отчёты: `data/corners-performance-exe-native-verification.json`, `data/corners-performance-exe-125-verification.json`. Содержимое всех пользовательских таблиц при миграции 6 → 7 полностью совпало до первого открытия обновлённого приложения; integrity_check=ok.
